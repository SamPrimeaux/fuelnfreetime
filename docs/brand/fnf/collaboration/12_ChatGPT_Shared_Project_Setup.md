# 12 — How Justin and Sam Can Use One Shared ChatGPT Project

**Checked against:** OpenAI's official Projects help documentation, October 6, 2026.  
**Official source:** https://help.openai.com/en/articles/10169521-projects-in-chatgpt  
**Goal:** One shared context and decision history even when schedules rarely overlap.

## The best setup: ONE joint project

Recommended name: **Fuel N Free Time — Brand & Builds**  
Members: Justin + Sam.  
Project owner: whichever account should control long-term access; for a small brand, this is an explicit ownership decision, not automatically the first person who creates it.

Choose **invite-only** sharing rather than a public "anyone with link" invitation. Use **Edit access** for the other core collaborator so both can upload files and revise project instructions (subject to each account's available permissions).

### Step 1 — Create project (on web or mobile)

1. Open ChatGPT while signed into your own account.
2. In the left sidebar, select **New project**.
3. Enter the recommended name; select an icon and color if desired.
4. Open the project's `•••` menu → **Project settings**.
5. Paste the contents of `13_Copy_Paste_Project_Instructions.md` into **Project instructions** and save.
6. Optional: Create a simple first chat named `WELCOME / HOW WE'LL WORK` and say which materials are drafts.

**Tip:** Project instructions apply only within this project and can override your general ChatGPT custom instructions there.

### Step 2 — Add this handoff as project sources

1. Extract the downloaded ZIP on your device; you'll see **separate Markdown files**.
2. Open the project → its files/sources area → **Add files** or equivalent, and choose the individual `.md` files.
3. Begin with `00`, `01`, `02`, `03`, `04`, `06`, `07`, `10`, `11`, `12`, `13`, `15`. Add the remaining docs as space allows, or add all 16 if plan limits allow.
4. Upload a small set of original user-owned reference photos: real hourglass front/back, F&FT chest logo, actual caps and tumbler, major aviation concepts, the badge proof sheet and the red bike photo. Select only assets you are authorized to share.
5. Treat the larger **logo-master ZIP** as a separate archive. For detailed design review, upload the **proof sheet + specific SVG/PNG** rather than assuming ChatGPT can interpret every file inside a ZIP.
6. Keep a separate permanent copy outside ChatGPT. The project is a collaboration context, not the only asset repository or production source control.

**File limits:** According to the official help page at the time of writing: shared Projects support **up to 25 files for Plus and Go owners**, **5 for Free** and **40 for Pro**, with collaborator limits also varying by plan. Plan for fewer files if the owner is on Free. There are 16 `.md` documents in this kit (including this one); upload the most important first if space is tight. Check the help page for changes.

### Step 3 — Share with each other

1. Inside the Project, select **Share**.
2. Choose **Only those invited** (recommended).
3. Invite the collaborator's ChatGPT account email, and grant **Edit** access for the two core collaborators.
4. Send the invite; the other person accepts using their ChatGPT account.
5. Verify the project appears in both accounts and both can see `00_START_HERE.md` and the chats.
6. Keep permissions limited to the people who should see supplier costs, design drafts, creator communications and other non-public information.

**Access differences:** Edit members can upload/remove files and update instructions; Chat members can read and create chats but generally can't change the project sources/instructions or invite people. The owner controls member access and removal. Anyone you add may see files and chats in the shared project.

### Step 4 — Divide work by chats, not by separate disconnected projects

Recommended separate conversation names:

- `01 BRAND — Justin's voice and decisions`
- `02 VISUAL — logos, colors, product identity`
- `03 PRODUCT — stock, photography, collection pages`
- `04 CONTENT — reels, creator stories and scripts/outlines`
- `05 BIKE — pickup, wrap project and permissions`
- `06 SITE — pages, CMS and SEO`
- `07 WEEKLY DECISIONS — what is approved`

Use branches when you want to experiment with two directions without overwriting a teammate's original thread. Shared project chats are **not** a real-time co-editing conversation; each person can create/branch chats, and collaborators can read them afterward.

### Step 5 — Use ChatGPT as your asynchronous creative coordinator

Justin can say:

> "Read the FNF Project sources. I only have 7 minutes. Ask me three high-impact questions that Sam needs answered. Don't assume I approved previous ideas."

Sam can say:

> "Review the FNF Project chats created since our last decision summary. Separate Justin's actual approvals, new ideas, open questions and claims needing verification. Draft an updated decision list with source chat references. Do not invent answers."

Justin can send more photos and say:

> "Sort these photos into REAL PRODUCT / CONCEPT / LOGO / STORY, suggest the best collection fit and tell Sam what needs verifying before the CMS publishes them."

To avoid information loss, summarize decisions in `WEEKLY DECISIONS`, and, when possible, save important responses as project sources or update the canonical decision document in the shared file location.

### Step 6 — What is and isn't "syncing"

**What sharing does:** Both people can access shared project files, instructions and chats. New chats can use the project's shared context. You can continue from another person's materials and branch discussions.

**What it does not do:** It does not automatically merge your separate personal ChatGPT histories, memories, private projects, contacts, local repositories, Drive folders or unpublished drafts. Shared projects use **project-only memory** and cannot use personal context outside that shared project. It is not a Git repository, live collaborative CMS, shared inbox or guaranteed version history for files. File changes outside the project aren't inherently reflected unless the source is updated; take care with duplicate file uploads.

**Important privacy:** All invited members can see shared chats and source files; only add what both are meant to access. Don't upload customer addresses, access tokens, unpublished partner contracts or private creator correspondence without permission and appropriate controls.

### Step 7 — Pick a real "source of truth" for approvals

Recommended simple setup:

- **ChatGPT Project:** Ideas, conversation, summaries, creative iteration, Q&A.
- **Canonical docs folder or versioned repo:** Latest approved Markdown, recorded decisions, media rights/usage notes, proof sheets and final source art.
- **Actual product/CMS system:** Pricing, SKUs, stock, page content and published media.
- **Manufacturer system:** Final tech packs, physical samples, approved production exports.

A project conversation that says "we like gold" should not automatically change a product, supplier file or live site.

## If one of you has only a free account

Shared Projects are offered on Free as well as paid plans, but file/collaborator limits differ. Whoever owns the project determines key limits. A paid account can own the workspace for a larger source set; the other person can join with the permissions offered. If either user cannot access sharing due to workspace policy or feature availability, use a shared folder containing these Markdown files and create a joint project once sharing is enabled. Never interpret lack of access as permission to share an account or credentials.

## A productive weekly loop

**Justin:** 5–10 minutes, one real photo batch and a voice note saying what he likes/dislikes.  
**Sam:** Ingest and categorize; make one visual or site revision; write a 5-bullet weekly sync.  
**Justin:** Quick approve/reject/park.  
**Sam:** Record approvals; publish only after the necessary factual/production/legal checks.
